# IP-Music 需求文档

> 版本：v1.0
> 状态：已确认
> 最后更新：需求确认阶段

## 1. 项目概述

### 1.1 一句话描述

输入 Bangumi 用户 ID，查看自己看过/玩过/读过的作品，点击作品即可收听该作品相关的音乐（完整曲目），并可查看歌词与翻译。

### 1.2 项目目标

- 让 Bangumi 用户能够方便地回顾自己收藏的作品，并直接听到相关音乐
- 全程使用**合规**的音乐来源，不绕过任何平台的版权限制
- 网站可公开访问，任何人输入 ID 即可使用，无需注册登录

### 1.3 非目标（明确不做）

以下内容经讨论后**明确排除**，原因见括号：

- ❌ **网易云扫码登录**（网易云正在封杀第三方模拟登录，会导致访客账号被冻结 3~7 天并强制重置密码）
- ❌ **抓取网易云音频直链**（绕过版权限制，违反服务条款，且实测大部分歌曲匿名拿不到直链）
- ❌ **站内播放网易云完整歌曲**（技术上不可行且不合规）
- ❌ **用户账号体系 / 数据库**（第一版即查即走，无持久化）
- ❌ **音乐条目类型（subject_type=3）**（音乐条目本身就是专辑，与"找它的音乐"语义重叠）

## 2. 用户场景

### 2.1 核心流程

```
用户打开网站
    ↓
输入 Bangumi 用户 ID（如 sai）
    ↓
选择作品类型（动画 / 游戏 / 书籍）与收藏状态
    ↓
看到作品列表（封面 + 名称）
    ↓
点击某个作品
    ↓
展开该作品的音乐列表（来自 B站，优先 OST / 音乐合集）
    ↓
点击音乐 → 站内播放（B站官方播放器）
    ↓
（可选）点击"歌词" → 显示网易云歌词 + 中文翻译
    ↓
（可选）点击"去网易云" → 新标签页跳转网易云搜索
```

### 2.2 典型用户

- 有 Bangumi 账号、收藏了大量动画/游戏/书籍的用户
- 想快速回顾某个作品的原声带、主题曲
- 希望有中文翻译歌词（尤其是日文歌曲）

## 3. 功能需求

### 3.1 作品列表（F1）

| 项 | 说明 |
|---|---|
| F1.1 | 输入 Bangumi 用户 ID（用户名，如 `sai`） |
| F1.2 | 支持按作品类型筛选：动画(2) / 游戏(4) / 书籍(1) |
| F1.3 | 支持按收藏状态筛选：想看 / 在看 / 看过 / 搁置 / 抛弃 |
| F1.4 | 每个条目显示：**封面图 + 作品名称**（第一版仅此两项） |
| F1.5 | 名称优先显示中文名（`name_cn`），无中文名时回退原名（`name`） |
| F1.6 | 分页加载（Bangumi 单次最多 50 条） |

**数据来源**：`GET https://api.bgm.tv/v0/users/{username}/collections`

- 参数：`subject_type`、`type`、`limit`（最大 50）、`offset`
- 返回：`{ total, limit, offset, data: [{ subject_id, subject_type, type, rate, subject: { id, name, name_cn, images } }] }`
- **必须携带 `User-Agent` 请求头**（Bangumi 强制要求）

### 3.2 音乐列表（F2）

| 项 | 说明 |
|---|---|
| F2.1 | 点击作品后，展示该作品相关的音乐视频列表 |
| F2.2 | **优先展示 OST / 音乐合集**（搜索关键词策略） |
| F2.3 | 每条显示：视频标题、UP主、时长、播放量、封面 |
| F2.4 | 点击即可在站内播放 |

**数据来源**：`GET https://api.bilibili.com/x/web-interface/search/type`

- 参数：`search_type=video`、`keyword`、`page`
- 关键词策略：`{作品名} OST`、`{作品名} 主题曲`、`{作品名} 音乐合集`
- 排序：优先时长较长的合集类内容
- ⚠️ **风控注意**：实测连续请求会返回 `HTTP 412`，需带完整浏览器请求头并控制请求频率

### 3.3 站内播放（F3）

| 项 | 说明 |
|---|---|
| F3.1 | 使用 **B站官方 iframe 播放器**嵌入播放 |
| F3.2 | 播放器地址：`https://player.bilibili.com/player.html?bvid={bvid}&page=1` |
| F3.3 | 同一时间只播放一个视频（点击新视频时替换当前播放器） |
| F3.4 | 播放器需支持自适应宽高 |

**合规性说明**：`player.bilibili.com` 未设置 `X-Frame-Options` 与 CSP 限制，官方允许外站嵌入。用户播放行为发生在 B站官方播放器内，播放量、广告均归属 B站，属于 B站鼓励的分享方式。

### 3.4 歌词与翻译（F4）

| 项 | 说明 |
|---|---|
| F4.1 | **按需加载**：不点击不请求（用户明确要求） |
| F4.2 | 点击"歌词"按钮后，显示原文歌词 + 中文翻译 |
| F4.3 | 翻译不存在时，仅显示原文并给出提示 |
| F4.4 | 歌词需解析 LRC 时间轴格式，按行展示 |

**数据来源**：`GET https://music.163.com/api/song/lyric?id={id}&lv=1&kv=1&tv=-1`

- 返回：`{ lrc: { lyric }, tlyric: { lyric } }`
- **匹配链路**：B站视频标题 → 清洗标题 → 网易云搜索 `GET /api/search/get/web?s={关键词}&type=1` → 取首个结果 ID → 请求歌词
- **合规性说明**：歌词为文本元数据，非版权音频，且该接口无需登录

### 3.5 跳转网易云（F5）

| 项 | 说明 |
|---|---|
| F5.1 | 每首歌提供"去网易云"按钮 |
| F5.2 | 新标签页打开网易云搜索页：`https://music.163.com/#/search/m/?s={关键词}` |
| F5.3 | 用于满足用户听完整版/中文曲库的需求 |

## 4. 技术方案

### 4.1 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | **Next.js 14（App Router）** | 前后端一体，API Route 做代理规避 CORS |
| 语言 | TypeScript | 类型安全，便于维护 |
| 样式 | Tailwind CSS | 快速开发，无需额外 CSS 文件 |
| 部署 | 本地优先，后续可上 Vercel | 用户选择"先本地跑通" |

### 4.2 架构

```
浏览器
  ↓
Next.js 前端页面
  ↓
Next.js API Routes（服务端代理，规避 CORS + 统一 UA/请求头）
  ├── /api/bangumi/collections  → api.bgm.tv
  ├── /api/music/search         → api.bilibili.com
  └── /api/music/lyric          → music.163.com
```

**为什么必须用服务端代理**：
1. Bangumi 强制要求 `User-Agent`，浏览器无法自定义该请求头
2. B站接口有风控，需要服务端统一管理请求头与频率
3. 规避浏览器 CORS 限制

### 4.3 关键约束与风险

| 风险 | 影响 | 应对 |
|---|---|---|
| Bangumi API 在开发沙箱不可达 | 无法本地联调 | 按 OpenAPI 规范实现，用户本地验证 |
| B站搜索风控（HTTP 412） | 搜索失败 | 完整浏览器头 + 请求间隔 + 失败重试 |
| B站接口非官方公开 API | 可能变更 | 封装为独立模块，便于替换 |
| 网易云歌词接口非官方 | 可能变更 | 失败时降级为"暂无歌词"，不影响主流程 |

## 5. 界面设计

### 5.1 页面结构

**单页应用**，三个区域：

1. **顶部搜索区**：用户 ID 输入框 + 类型/状态筛选 + 查询按钮
2. **作品网格区**：封面 + 名称的卡片网格
3. **详情面板**：点击作品后展开，含音乐列表 + 播放器 + 歌词区

### 5.2 交互要点

- 点击作品卡片 → 展开详情面板（不跳页）
- 点击音乐条目 → 播放器区域加载对应视频
- 点击"歌词" → 歌词区异步加载，显示 loading 状态
- 所有异步操作需有 loading / error 状态反馈

## 6. 验收标准

- [ ] 输入有效 Bangumi 用户 ID，能正确显示作品列表（封面+名称）
- [ ] 类型筛选（动画/游戏/书籍）与状态筛选生效
- [ ] 点击作品能加载出相关音乐列表
- [ ] 点击音乐能在站内播放（B站官方播放器）
- [ ] 点击"歌词"能显示原文 + 翻译，且未点击时不发请求
- [ ] "去网易云"按钮能正确跳转
- [ ] 无效用户 ID / 网络错误有友好提示
- [ ] 页面在移动端可正常使用

## 7. 后续可扩展方向（不在第一版）

- 用 Bangumi 关联音乐条目（`/v0/subjects/{id}/subjects`）提升匹配准确率（原方案 B）
- 加轻量缓存减少 API 调用
- 支持更多音乐源（QQ音乐、YouTube Music）
- 收藏/历史记录（需数据库）
